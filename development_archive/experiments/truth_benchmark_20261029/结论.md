# 世界关真值基准：结果与结论

本轮完成 **168 / 168** 次测试：20张植入可解图、20张随机配牌图、2张原始世界关，各用4种算法测试一次。每次求解预算10秒、单路、单任务私有内存上限1536 MB；最多12个任务并行。

**最重要的发现：此前两张未解出的世界关，现在都找到了完整231步路线。它们在当前无道具普通牌规则模型下有解。**

本轮没有点击游戏。完整路线经过独立矩形/牌槽回放、项目既有Python回放，以及C#执行器的 `--validate-only` 回放。C#验证使用离线坐标归一化，仅检查规则与坐标边界，不代表已经完成实机截图对齐。

测试结束后，还把已知可解的25张地图（20张植入、3张随机、2张原始图）的见证按同色支配约束定序，再固定给同一CP-SAT模型核查，25张均被模型接受。因此本轮CP-SAT的0出解不能用“这些已知见证不符合模型”来解释；该事后核查不计入基准解出率。记录见 `model_witness_audit.json`。

## 3. 此前配置为什么会失败

对当前世界关使用同一原生二进制、同一原始地图、同一种子1997做顺序复查：

| 设置 | 结果 |
|---|---|
| 原快速路径：`solve_first=0`、1.5秒、200万状态上限 | 约1.55秒因时间限制停止，未出解 |
| **只把时间预算改成10秒**，其余保持原值 | **约2.62秒，1665535个状态，完整解** |
| `solve_first=0.8`、10秒、200万状态上限 | 约3.08秒触及状态上限，未出解 |
| `solve_first=0.8`、10秒、4000万状态上限 | 约4.92秒，3117941个状态，完整解 |

因此，至少对当前这张地图，原快速路径被过短的时间预算提前截断；换另一排序时，过小的状态上限也会截断可成功的搜索。先前把主要预算转给当前表现较弱的CP-SAT，并且在已有部分提示时跳过新的快速尝试，不是合适的默认路由。

参数复查是基准之后的顺序实验，机器负载与主基准不同，不能把两处用时当作精确速度比。命令、参数、状态与答案保存在 `parameter_check/`。

## 4. 基准是否有真值泄漏

- 40张生成图全部保持世界关的同一覆盖布局与每种牌的原始数量。
- 20张植入图的独立见证全部验证通过。槽上限4、5、6格分别有7、7、6张，实际见证峰值与档位一致。
- 植入时使用随机、偏挖深、偏展开的合法顺序，避免只用一种拓扑取牌方式。
- 求解输入只含 `levelData`，文件名是内容哈希形成的不透明编号，不含组别、植入路线或生成种子。
- 见证单独放在 `private/witnesses/`；工作进程命令不包含见证、manifest、hint、固定路线或冲突缓存。主进程单独做验收。
- 原版Python、原生tight-top、束搜索和CP-SAT均使用新进程、空输出目录和固定设置；没有读取历史答案缓存。

上述是输入与代码路径隔离，不是操作系统级文件权限沙箱。程序没有尝试读取输入以外的真值文件。

## 5. 可以和不可以得出的结论

1. **两张真实世界关都有完整解**，此前“久算不出，可能本来无解”的判断不适用于这两张图。
2. 在本轮同布局植入样本上，tight-top明显优于当前Python原版、束搜索和CP-SAT模型，应该优先研究和配置这条有效路径。
3. 随机重排样本至少3/20可解；其余17张没有标签。此批样本真实可解比例仍只能约束在 **15%～100%**，不能据此声称85%无解。
4. 这些随机图来自均匀重排既定牌型多重集合，不代表游戏服务器的实际出题分布。
5. 植入图有生成偏差，小样本不是所有可解实例的代表；结果也不是通用算法强弱排名。
6. 此次得到的是离线完整答案和配置证据，**尚未实机执行第二关**。

## 6. 文件入口与复现

- `REPORT.md`：完整统计及分档结果。表格中的“真值未知”是测试前的分组标签；本文件和统计边界给出测试后的已知情况。
- `report.html`：图形化表格与完整说明。
- `manifest.json`：42张地图、源SHA、布局SHA、生成种子及真值见证索引。
- `protocol.json`：预算、并发、版本、参数、源代码和二进制SHA。
- `runs/`：168次独立运行的完整命令、原始日志、资源统计、候选及验收结果。
- `results.json`、`summary.json`：机器可读结果。
- `repro_sources/`：与记录SHA一致的本次核心脚本和二进制快照。

同目录再次执行原运行命令，会核对协议与地图后跳过已完成结果；不会把历史完整答案作为新的求解输入。改变脚本、预算或其他协议字段时应生成新的实验目录。
