流程：优先验收普通完整缓存；没有普通答案时验收已有道具缓存；再跑普通搜索，失败后利用合法部分路线及容量探测结果搜索一次移出。普通成功结果仍走原有完整回放和执行保护；道具成功只展示并保存。

### 道具归约的要点

在候选前缀使用移出后，把被移出的三张牌建成三个独立可取的 `B~` 虚拟牌；用 `P~` 幻影取牌校正各牌型模 3 的槽内余数。原生解必须保留检查点前缀，尾部不得含未处理的 `P~`。再把 `B~` 转回实际点回动作，回到原始地图按真实容量完整验收。

合成地图带 `_constraint_relaxation=True`，不得导出成普通执行答案。候选搜索成功不等于产品答案成功；只有双回放清空三个区域才保存道具结果。

## 6. 预算、结果格式与缓存边界

默认 `seconds=60`。对剩余牌数大于 60、预算至少 15 秒的普通关，移出预算为 `min(20, seconds/3)`，普通预算为总预算减去移出预算。默认对应：原生最多 32 秒，CP-SAT 最多 8 秒，移出最多 20 秒；容量诊断与 CP-SAT 阶段并行。不同阶段可能提前结束，不保证消耗满预算；进程回收与文件验收存在少量额外开销。

移出搜索最多两路，每路时间片最多三秒，按可用内存估计状态上限，并采样私有内存；超时或取消后回收自有进程。只枚举候选路线合法前缀末端附近的移出位置：窗口 60 步、步长 3。它不是穷举所有移出时机，没有候选或预算耗尽只能返回未知。

代码允许显式设置其他预算；60 秒是当前默认与保存设置，不是所有调用的硬性全局上限。已有缓存验收不需要重跑整轮搜索。

| 分类 | 关键字段 | 对应处理 |
|---|---|---|
| 普通完整路线 | `validated=true`，普通 `sequence` | 保存到 `complete/solution.json`；实际执行前仍核对地图/前缀/画面 |
| 道具完整规划 | `execution_kind=manual_move_out_v1`、`prop_validated=true`、`validated=false`、`executable=false` | 保存到 `prop/solution.json`，使用结构化 `actions`；控制器进入 `prop_ready`，`auto=false`、`ready=None` |
| 限时未找到 | `limited` / `unknown` | 保存诊断，不能当作无解或可执行路线 |
| CP-SAT 模型不可满足 | 模型范围内 `infeasible` | 仍须写明前缀与模型范围；不是已独立复核的完整无解证书 |

道具动作只有 `board`、`move_out`、`return`。缓存每次复用都回放；地图 SHA 或已确认前缀不匹配应失效。普通完整缓存与道具缓存分开，不能通过修改 `validated` 绕过执行保护。
