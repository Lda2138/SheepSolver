# 开局自动获取种子和完整地图

## 新增：被动结算数据校验路径

安装包源码显示，`gameOver()` 对 URI 编码后的 JSON 正文使用 AES-OFB 加密，再将密文和版本号添加到同一份正文发送。新增 `game_known_plaintext.py` 可在内存中由这份明密文恢复对应的加密流，用种子请求中已知的请求标识验证前缀完全一致后，才尝试解码种子响应。不会修改请求、提交额外结算或持久化正文/加密流。

这条路径已通过本机真实游戏验证：2026-10-08 的世界关卡已取得四个真实种子字，并还原第一关 18 张、第二关 255 张完整牌型。真实请求为 URL 编码表单，HTTP 层按字母排序字段；程序已按安装包 `reportData()` / `gameOver()` 的加密前顺序重建 JSON，验证种子请求前缀后成功解码完整响应。首次使用需要监听期间正常完成或结束一局来捕获结算；保持小程序运行，再开下一局。换密钥、IV 或关掉小程序后，可能需要重新捕获结算。

抓取器位于 `auto_capture.py`，在原项目旁运行。获取真实地图后，使用原项目的 `ShuffleHelper` 和 `business/SheepSolver.py`；求解结果由独立的遮挡、七槽和三消规则回放校验。

## 使用

1. 双击「启用自动抓取.bat」。按本会话已经给予的授权，脚本显示临时证书和代理设置并直接启用。
2. 查看 http://127.0.0.1:8766 的本地状态页。
3. 在微信小程序里正常开始一局游戏。已有棋盘不会因为启动抓取器就重新发出开局请求；需要在监听期间真正进入新一局。
4. 等待页面显示完整地图。标准关卡自动按原项目“高层优先”策略求解，默认限时 120 秒；加速器未编译时使用原 Python 实现。
5. 结束时双击「停止自动抓取.bat」。它恢复运行前的代理，并移除本次新加入的证书。默认最多运行 4 小时。

后台程序不会移动鼠标、抢窗口焦点或点击游戏。自动点击需要在真实地图、求解结果和当前棋盘对齐之后执行。

## 自动处理流程

- 监听游戏 `map_info_ex` / `game_start` 开局响应。
- 获取 `map_md5`、`map_seed`、`map_seed_2` 和是否需要单独种子的标记。
- 自动从游戏 CDN 下载 `.map`，去除 21 字节头，解码 Protobuf 全层地图。游戏自行下载的地图也会被捕获。
- 若游戏返回 `match_data`，按安装包里的 LZ-string UTF16 规则解压，提取 `allBlockRuntimeData` 中的完整牌型和坐标。
- 若地图中的类型为 0，必须等真实种子，并按原项目洗牌算法补齐。
- 单独种子接口支持普通 JSON、Protobuf，以及取得本机游戏解密参数后的 AES-OFB 响应解密。解密参数只保留在内存。
- 重新开局建立新的局号，清除上一局的当前地图别名，丢弃晚到的上一局种子。

## 文件与状态

- `output/auto_capture/status.json`：当前局状态，`complete: true` 才表示牌型齐全；`seed_received` 单独表示真实种子是否取得。
- `output/auto_capture/sessions/<局号>/start_map_info.json`：开局字段白名单。
- 同目录 `seed.json`：已解析的真实种子（若取得）。
- 同目录 `map_0.json`、`map_1.json` 等：各关完整地图。
- 同目录 `solution/solution.json`、`solution/点击预演.html`：原项目求解与验证结果。
- `output/current_game_map.json`：最后一关的当前完整地图快捷副本。以状态文件中的局号和 `current_map` 路径为准。
- `output/auto_capture/service_lease.json`：临时配置的恢复记录，请保留到服务停止。

完整地图与真实种子是分别标记的。若新版 `match_data` 已给出所有牌型，地图可以先完整；此时种子仍可能显示等待。

## 当前边界

新版种子还存在一层游戏自己的加密，HTTPS 解密本身不能消除它。工具对游戏主进程进行只读、限时的显式 `getLatestUserKey` 回调 JSON 查找；是否找到实际密钥取决于运行时是否保留该对象文本，尚未经过这台电脑的真实开局验证。找不到时显示“等待游戏的解密参数”，不会用零种子或密文生成答案。

特殊牌、金牌规则和已进行的牌槽/移除区状态会被标记，暂不交给旧求解器自动求解。求解器使用原仓库算法，限时内不保证一定找到解。

协议回归测试使用构造数据，涵盖二进制地图解码、原项目洗牌一致性、种子编码、AES 参数、局间隔离、压缩地图、字母排序表单重建，以及答案回放。另已验证真实开局抓取、完整种子响应、两关地图，并将实际可见牌型和地图逐项对应。第一关 18 步、第二关 255 步已通过独立后台程序实际执行完成。游戏最终显示“恭喜你，挑战成功”与明信片奖励。通关证据为 `output/game_completion.png`、该局 `completion.json` 及 `main_play/actions.jsonl`。

本机服务已由普通 Windows 用户会话成功启用。代理与 CA 仍由用户启动的监督进程负责恢复；不要直接杀掉监督进程。执行环境内的证书导入曾无法确认，因此启动器遇到这种情况会恢复配置退出，可从文件资源管理器运行「启用自动抓取.bat」。

## 完整答案的独立后台执行

`SolverPlayback.exe` 使用校准后的地图牌编号坐标，逐步显示穿透、无焦点的红框，并用 Windows 后台消息点击微信渲染窗口。不会移动系统鼠标或自动切换前台。每步检查目标图案、窗口位置、牌面变化和牌槽数量。Esc/F9 停止，F8 暂停/继续。不一致时停止，不能直接重放旧开局计划。

`native/solver/FastOriginalSolver.cs` 是原项目策略的加速实现，保留遮挡图、七槽剪枝、同类牌优先顺序和可见牌状态缓存。30 个确定性小地图测试的答案与原 Python 实现完全相同；原代码仍保留。它支持内存和时间上限；限时无解不代表地图无解。`solve_original_batch.py` 只导出经过独立规则回放的完整答案。

## 临时配置的范围

HTTPS 抓取需要当前 Windows 用户信任本项目的 mitmproxy CA，并临时使用 `127.0.0.1:6666` 代理。仅 easygame2021.com 及其子域名被 HTTPS 解析；其他 HTTPS 请求走 CONNECT 隧道。程序不保存完整流量、请求头、微信令牌或账号信息。

服务和状态页只监听本机回环地址。停止时逐项恢复仍保持程序设置值的配置，保留用户运行期间另行修改的值；已有受信任证书不删除。异常退出后再运行停止脚本可用恢复记录恢复配置。

## 命令行

只检查，不修改系统：

```powershell
.\venv\Scripts\python.exe capture_service.py check
```

仅启动本地服务测试，不启用代理、不信任证书：

```powershell
.\venv\Scripts\python.exe capture_service.py start
```

已批准临时设置后启用（服务已运行时先停止）：

```powershell
.\venv\Scripts\python.exe capture_service.py start --enable-proxy --trust-ca
.\venv\Scripts\python.exe capture_service.py stop
```

运行协议测试（lzstring 只用于独立生成测试数据）：

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-capture-test.txt
.\venv\Scripts\python.exe -m unittest discover -s tests -p test_auto_capture.py -v
```
