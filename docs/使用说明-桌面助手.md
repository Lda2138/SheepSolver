# SheepSolver 桌面助手配置

## 已验证

- 已有 `venv` 的 Python 3.13 和 mitmproxy 12.2.3 可用，`pip check` 通过。
- 原仓库的 `online_data.json` 是示例地图。求解器算出 255 步，并通过独立回放校验：每一步可取、牌槽不满、最终棋盘和牌槽都为空。
- 本次实机模拟点击了当前微信棋盘的一张玉米，已观察到它进入牌槽。
- 用户要求不影响电脑操作后，停止实机输入；后续配置、求解和绘图均在后台进行。

## 使用

双击 `后台求解.bat`，或在此目录运行：

```powershell
.\venv\Scripts\python.exe desktop_assistant.py
```

输出 `output/solution.json` 和 `output/点击预演.html`。打开 HTML 可单步点击红框，也可连续预演全部步骤。页面没有外部依赖，不控制鼠标或微信。默认展示的是仓库示例，不是当前微信的通关答案。

指定完整的开局地图：

```powershell
.\venv\Scripts\python.exe desktop_assistant.py --map .\my_game.json --source-label "自行导出的完整开局地图" --time-limit 30
```

要求地图含 `levelData`，每张牌有 `id`、`type`、`rolNum`、`rowNum`，所有牌类型已知，开局牌槽为空。程序不支持从中途的未知牌槽直接求解。限时无解会退出，不把部分结果导出为可点击答案。`--source-label` 只是说明文字，不是与实机匹配的证明。

重新安装 Windows 依赖使用 `setup_windows.ps1`；不必重复安装当前正常的环境。保留了上游要求旧版 mitmproxy 的 `requirements.txt`，新增 `requirements-windows.txt` 适配当前 Python。

## 当前微信截图标注

`output/当前棋盘-点击标注.png` 框选了观察当时可消除的三张青草，编号为建议顺序。`output/current_visible_plan.json` 保存了框的位置、中心坐标和截图尺寸。它来自第一张玉米点击后的截图，用户后续操作可能使它过期。

从已保存截图生成标注：

```powershell
.\venv\Scripts\python.exe annotate_clicks.py .\output\tutorial_after_first_click.png .\output\current_visible_plan.json --output .\output\当前棋盘-点击标注.png
```

## 连续实机点击的条件

上游只负责地图求解，没有图像识别、点击执行器或实时框选。仓库地图与当前微信棋盘不同；隐藏牌的类型不能从截图确定。实际整局求解需要当前局的完整地图与种子，且要校验可见牌、牌槽状态及坐标映射。

此前使用的内置 Windows 点击接口会激活目标窗口。现已新增独立程序 `SheepClicker.exe`，用后台窗口消息点击，并在当前微信中实测有效；不依赖内置操控工具。程序默认处于等待状态，支持框选、单步、连续执行和停止，详见 `独立点击程序说明.md`。当前自动图像匹配限于青草、胡萝卜和玉米，不能保证复杂第二关通关。
